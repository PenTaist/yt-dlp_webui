Documentation de l’API

L’interface web s’appuie entièrement sur cette API JSON. Une application tierce, comme un lecteur de musique, peut rechercher sur YouTube, lancer des téléchargements, suivre leur progression et récupérer les fichiers.

URL de base
https://yt-dlp.pentaist.fr
Format
JSON en entrée et en sortie, UTF-8
Authentification
Aucune, chaque client est identifié par un identifiant anonyme

Identification du client

Chaque tâche appartient au client qui l’a créée. Un client ne voit, ne suit, n’annule et ne télécharge que ses propres tâches. Une tâche d’un autre client répond 404, comme si elle n’existait pas.

Deux façons de s’identifier :

  • En-tête X-Client-Id, recommandé pour une application. Générez une fois une valeur aléatoire de 32 à 128 caractères parmi A-Z a-z 0-9 _ -, conservez-la et envoyez-la à chaque requête. Elle est prioritaire sur le cookie.
  • Cookie ytdlp_client, posé automatiquement par le serveur à la première requête. C’est ce qu’utilise le navigateur. Un client HTTP qui conserve les cookies fonctionne aussi de cette façon.

Sans en-tête ni cookie, chaque requête est vue comme un nouveau client : une tâche créée sera ensuite introuvable. Traitez l’identifiant comme un secret, car il donne accès aux tâches associées.

En-têtes obligatoires

En-têteQuandValeur
X-Requested-WithToutes les requêtes POST et DELETEfetch, sinon réponse 403
Content-TypePOST /api/jobsapplication/json
X-Client-IdToutes les requêtes, pour une applicationVotre identifiant de client

Démarrage rapide

Le cycle complet : rechercher, lancer, suivre, récupérer, nettoyer.

BASE=https://yt-dlp.pentaist.fr
CLIENT=$(openssl rand -hex 24)

curl -s "$BASE/api/search?q=bohemian%20rhapsody&type=songs&limit=3" \
  -H "X-Client-Id: $CLIENT"

curl -s -X POST "$BASE/api/jobs" \
  -H "X-Client-Id: $CLIENT" -H "X-Requested-With: fetch" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://music.youtube.com/watch?v=fJ9rUzIMcZQ","format":"mp3","quality":"0","playlist":false}'

curl -s "$BASE/api/jobs/{id}" -H "X-Client-Id: $CLIENT"

curl -OJ "$BASE/api/jobs/{id}/file" -H "X-Client-Id: $CLIENT"

curl -s -X DELETE "$BASE/api/jobs/{id}" \
  -H "X-Client-Id: $CLIENT" -H "X-Requested-With: fetch"

GET /api/search

Recherche sur YouTube (via yt-dlp) ou sur YouTube Music (via ytmusicapi). Rien n’est téléchargé. Les résultats sont mis en cache 10 minutes côté serveur.

typeNonvideos (par défaut) et playlists pour YouTube, songs et albums pour YouTube Music
limitNonNombre de résultats, de 1 à search_limit (20 par défaut), 10 si absent

POST /api/jobs

Lance un téléchargement. La réponse arrive immédiatement avec la tâche au statut queued ; le téléchargement se fait en arrière-plan.

Champ JSONObligatoireDescription
urlOuiLien http ou https d’une vidéo, d’un titre, d’une playlist ou d’un album, 2048 caractères au maximum. Tout site pris en charge par yt-dlp est accepté.
formatOuiVoir Formats et qualités
qualityNonVoir Formats et qualités. Une valeur invalide est remplacée par la meilleure qualité.
playlistNontrue pour télécharger toute la playlist quand le lien en contient une. Par défaut false : seul l’élément visé est téléchargé.

Réponse 201 avec l’objet tâche.

Une playlist ou un album est livré en un seul fichier .zip contenant un fichier par élément, numérotés dans l’ordre (01 - Titre [id].mp3). Si certains éléments échouent, la tâche se termine quand même avec les autres et le champ warning le signale.

GET /api/jobs

Liste les tâches du client, de la plus récente à la plus ancienne. Réponse : un tableau d’objets tâche.

GET /api/jobs/{id}

État d’une tâche. À interroger toutes les 1 à 2 secondes jusqu’à un statut final : done, error ou cancelled.

GET /api/jobs/{id}/file

Télécharge le fichier d’une tâche au statut done. Le nom est fourni dans l’en-tête Content-Disposition et dans le champ filename de la tâche. Les requêtes partielles (Range) sont prises en charge, ce qui permet de reprendre un transfert interrompu. Le fichier reste disponible jusqu’à la fin du délai de conservation, même après avoir été récupéré.

DELETE /api/jobs/{id}

Sur une tâche en cours (queued, running, processing) : l’annule, supprime les fichiers partiels et répond 200 avec la tâche au statut cancelled.

Sur une tâche terminée : la retire de la liste, supprime son fichier du serveur et répond 204 sans contenu. Pensez à le faire une fois le fichier récupéré pour libérer de l’espace.

GET /healthz

Sonde de disponibilité, sans identification. Répond {"ok": true}.

Formats et qualités

Typeformatquality
Audiomp3, m4a, opus, ogg0 meilleure (par défaut), 2 haute, 5 moyenne
Audio sans perteflac, wavIgnorée, la qualité de la source est conservée
Vidéomp4, mkv, webmbest (par défaut), ou hauteur maximale : 2160, 1440, 1080, 720, 480, 360

Les fichiers mp3 et m4a contiennent les métadonnées (titre, artiste, album quand elles existent) et la pochette. Les autres formats audio contiennent les métadonnées sans pochette. En vidéo, si la hauteur demandée n’existe pas, la plus proche en dessous est utilisée ; le format mp4 privilégie H.264 et AAC pour une lecture partout.

Erreurs et limites

Les erreurs de l’API renvoient un objet JSON de la forme {"error": "message lisible"}.

CodeCas
400Paramètre invalide : lien, format, texte de recherche ou type de recherche
403En-tête X-Requested-With: fetch absent sur un POST ou un DELETE
404Tâche inexistante, expirée ou appartenant à un autre client ; fichier pas encore prêt
429Trop de téléchargements en cours pour ce client ou pour le serveur, ou trop de requêtes
502Échec de la recherche côté YouTube
504YouTube a mis trop de temps à répondre à une recherche
LimiteValeur par défaut
Téléchargements en cours par client5
Téléchargements en cours sur le serveur20, dont 2 exécutés en parallèle
Éléments par playlist200
Durée maximale d’une tâche3 heures
Conservation des fichiers24 heures après la fin de la tâche
Lancements de téléchargement10 par minute et par adresse IP, avec une rafale de 5
Autres requêtes10 par seconde et par adresse IP, avec une rafale de 40

Les tâches sont gardées en mémoire : un redémarrage du service les efface, fichiers compris. Une application doit récupérer les fichiers puis les stocker elle-même plutôt que de pointer durablement vers ce serveur.

Exemples complets

Python

import time
import requests

BASE = "https://yt-dlp.pentaist.fr"
HEADERS = {"X-Client-Id": "mon-lecteur-7f3c9a1e5d2b8f4a6c0e9d1b", "X-Requested-With": "fetch"}

found = requests.get(f"{BASE}/api/search", params={"q": "daft punk", "type": "songs", "limit": 1},
                     headers=HEADERS, timeout=60).json()["results"][0]

job = requests.post(f"{BASE}/api/jobs", headers=HEADERS, timeout=30, json={
    "url": found["url"], "format": "mp3", "quality": "0", "playlist": found["playlist"],
}).json()

while job["status"] not in ("done", "error", "cancelled"):
    time.sleep(2)
    job = requests.get(f"{BASE}/api/jobs/{job['id']}", headers=HEADERS, timeout=30).json()
    print(f"{job['status']} {job['progress']} %")

if job["status"] == "done":
    with requests.get(f"{BASE}/api/jobs/{job['id']}/file", headers=HEADERS, stream=True, timeout=60) as r:
        r.raise_for_status()
        with open(job["filename"], "wb") as f:
            for chunk in r.iter_content(1 << 20):
                f.write(chunk)
    requests.delete(f"{BASE}/api/jobs/{job['id']}", headers=HEADERS, timeout=30)
else:
    print("Échec :", job["error"])

JavaScript

const BASE = "https://yt-dlp.pentaist.fr";
const HEADERS = { "X-Client-Id": "mon-lecteur-7f3c9a1e5d2b8f4a6c0e9d1b", "X-Requested-With": "fetch" };

async function call(path, options = {}) {
  const res = await fetch(BASE + path, { ...options, headers: { ...HEADERS, ...options.headers } });
  if (res.status === 204) return null;
  const data = await res.json();
  if (!res.ok) throw new Error(data.error);
  return data;
}

async function downloadTrack(url, format = "mp3") {
  let job = await call("/api/jobs", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ url, format, quality: "0", playlist: false }),
  });
  while (!["done", "error", "cancelled"].includes(job.status)) {
    await new Promise((r) => setTimeout(r, 2000));
    job = await call(`/api/jobs/${job.id}`);
  }
  if (job.status !== "done") throw new Error(job.error || "Téléchargement annulé");
  const blob = await (await fetch(`${BASE}/api/jobs/${job.id}/file`, { headers: HEADERS })).blob();
  await call(`/api/jobs/${job.id}`, { method: "DELETE" });
  return { blob, filename: job.filename };
}

Depuis une page web hébergée sur un autre domaine, le navigateur bloquera ces appels : l’API n’autorise pas les requêtes inter-domaines (CORS). Le code JavaScript ci-dessus convient à une application Node.js, Electron ou mobile, ou à une page servie par ce même domaine.
